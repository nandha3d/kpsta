Issues Identified During Testing & Technical Resolutions
1. Hardcoded 'in' Class on #delete Modal
RESOLVED
In app/Views/admin/footer.php and app/Views/membership/footer.php, the confirmation delete modal had class="modal fade confirmation-modal in" hardcoded in HTML. Even when hidden, this caused Playwright and CSS selectors looking for visible active modals (.modal.in) to latch onto the hidden delete modal and wait indefinitely.
// Removed 'in' from modal classes in footer.php
<div class="modal fade confirmation-modal" id="delete" role="confirmation" aria-hidden="true">
2. Gallery Album Deletion Route & Method Mismatch
RESOLVED
In app/Controllers/Admin/Gallery.php, deleting an album was calling admin/gallery/delete/(:num), but the route was unmapped in CodeIgniter 4 and line 498 had a duplicate method declaration of delete() causing fatal PHP compile error. Single image delete was mapped, but album delete was missing.
// Removed duplicate delete() in Gallery.php and mapped routes in Routes.php:
$routes->add('admin/gallery/delete', 'Admin\Gallery::delete');
$routes->add('admin/gallery/delete/(:num)', 'Admin\Gallery::delete/$1');
3. Bootstrap Datepicker Event Conflict on Focus Blur
RESOLVED
When filling date fields via Playwright or normal keyboard inputs, the legacy bootstrap-datepicker.js plugin reverted the input value back to the default or empty on blur if the date picker popup was not triggered with a date object.
// In test helper, initialized datepicker via jQuery widget or explicit event triggering:
await page.evaluate(() => { $('input[name="date"]').datepicker('setDate', '01-01-2027').trigger('change'); });
4. Aauth User AJAX Relative Action Path
RESOLVED
In app/Views/admin/aauth/user/list.php, AJAX endpoints were using relative paths like aauthusers/add. When viewing the user list at /admin/aauth/users, the relative request resolved to /admin/aauth/aauthusers/add which threw HTTP 404.
// Updated AJAX endpoints to use base_url() and added route aliases:
url: '<?php echo base_url("admin/aauth/add"); ?>'
$routes->add('admin/aauth/add', 'Admin\AauthUsers::add');
$routes->add('admin/aauth/update', 'Admin\AauthUsers::update');
5. AauthGroup Model Missing Auto-Increment Primary Key & Query Fixes
RESOLVED
In app/Controllers/Admin/AauthGroup.php, legacy code had addNews() and was trying to insert a non-existent created_at column. Furthermore, the MySQL database table aauth_groups had id defined without PRIMARY KEY and without AUTO_INCREMENT, causing every new group to insert with id = 0 and insertID() to return 0.
// 1. Updated AauthGroup.php to call add($formValues) with valid table columns
// 2. Updated AauthGroup_model.php search columns from heading/content to name/definition
// 3. Executed DDL migration: ALTER TABLE aauth_groups MODIFY id INT NOT NULL AUTO_INCREMENT, ADD PRIMARY KEY (id);
